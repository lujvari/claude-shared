# Plan 0003 — Box tooling for .NET and SQL Server work

**Spec:** specs/0003-box-dotnet-sql-tooling.md
**Effort:** medium
**Status:** done

## Approach

Image-only change, following the existing tool pattern: an `ARG` version plus hash, checked before unpacking, installed under `/opt` (the `claude-code-root` volume masks `$HOME` at runtime, so nothing baked can live there). The new blocks go after the Go block, so a bump to them rebuilds only the lighter layers below. No `run.sh` change.

- **SQL client (REQ-1):** go-sqlcmd v1.11.0 is published only as `.tar.bz2` for linux amd64 and arm64, and the image has no bzip2. The block checks `sha256sum -c`, unpacks `sqlcmd` and `NOTICE.md` with Python's `tarfile` into `/opt/sqlcmd` (no apt layer for one archive) and symlinks `sqlcmd` into `/usr/local/bin`.
- **Deployment tool (REQ-2):** the `microsoft.sqlpackage` 170.6.60 .NET tool. The `.nupkg` is downloaded from nuget.org and checked with `sha512sum -c`, then installed with `dotnet tool install --version 170.6.60 --framework net8.0 --tool-path /opt/sqlpackage --configfile <file>`, where the config `<clear/>`s every source except the local directory, so only the checked file can be installed. It needs runtime 8.0.34 and the image had 8.0.31, so SDK 8 is bumped from 8.0.425 to 8.0.428, which bundles 8.0.34. That is the root fix; a roll-forward wrapper would run the tool on runtime 9. `sqlpackage` is symlinked into `/usr/local/bin`. Framework-dependent, so one hash covers both architectures.
- **Python browser automation (REQ-3):** `playwright==1.62.0`, whose Chromium is 151, the same major as the pinned Chrome for Testing (151.0.7922.77). It is installed as root into the system Python (3.14, which comes in with `nodejs`) using `uv pip install --system --break-system-packages --no-cache --require-hashes`. The requirements file is copied from `claude-docker/playwright-requirements.txt`, which is generated by `uv pip compile --universal --generate-hashes`. Scripts launch the bundled browser through the existing `CHROME_EXECUTABLE`; no Playwright browser is downloaded. The build fails if Playwright's Chromium major differs from `CHROME_FOR_TESTING_VERSION`'s, so a bump of one without the other is caught. Chrome for Testing is x86_64-only, so arm64 boxes ship no browser, and REQ-3 doesn't apply to them.
- **Relative worktrees (REQ-4):** `EnableSourceControlManagerQueries=false` in the .NET `ENV` block. MSBuild reads it as a property and skips the SourceLink git read that rejects `extensions.relativeWorktrees`. Assemblies built in a box carry no commit SHA; release builds come from CI.

## Changes

- `claude-docker/Dockerfile` — SDK 8 bumped to 8.0.428 with its hashes. ARGs `SQLCMD_VERSION`, `SQLCMD_SHA256_X86_64`, `SQLCMD_SHA256_AARCH64`, `SQLPACKAGE_VERSION` and `SQLPACKAGE_NUPKG_SHA512`, each right above its own block so a bump only rebuilds that block. Three install blocks after the Go `ENV`. `EnableSourceControlManagerQueries=false` added to that `ENV`. A playwright note on the CfT ARG comment. A `COPY` of the requirements file.
- `claude-docker/playwright-requirements.txt` — new, hashed pins.
- `claude-docker/README.md` — bundled CLI line (`sqlcmd`, `sqlpackage`, Python `playwright`), and how Python Playwright gets the browser.
- `specs/CURRENT.md` — at closeout, under "Bundled tools and package managers".

## Dependencies

go-sqlcmd (GitHub releases), sqlpackage (nuget.org), playwright and its dependencies (PyPI). The host rebuilds the image.

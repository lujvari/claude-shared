## External CLIs and credentials

- The image ships `gh`, `glab` and AWS CLI v2 on the default PATH for both amd64 and arm64; `glab` and `aws` are pinned to a version and checked against a per-architecture sha256 at build time. (0001)
- The image ships `tfenv` and `tofuenv` on the default PATH, each pinned by a Dockerfile `ARG` version and checked against an `ARG`-pinned sha256 kept in version control, never fetched at build time. (0001)
- No `terraform` or `tofu` version is preinstalled: the `terraform` and `tofu` dispatcher shims are on PATH, and a project fetches its pinned binary at runtime with `tfenv install` or `tofuenv install` (typically from `.terraform-version` or `.opentofu-version`). (0001)
- Host credentials reach a box only through a per-run opt-in flag; with no flag, `run.sh` mounts no credential file and forwards no token. (0001)
- Every credential bind mount is read-only, and the host `~/.aws/credentials` and `~/.aws/cli/cache/` are never mounted, even under `--aws`. (0001)
- `--aws` mounts the host `~/.aws/config` at `/home/claude/.aws/config:ro` and, when present, `~/.aws/sso/` at `/home/claude/.aws/sso:ro`, and forwards no ambient `AWS_*` variable, so a static key never shadows a mounted SSO profile. (0001)
- Under `--aws`, static keys from the host `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` and `AWS_REGION` reach the box only as a named profile that the entrypoint writes into the box's `~/.aws/credentials`; the profile name is `CLAUDE_DOCKER_AWS_STATIC_PROFILE`, default `aegon`. (0001)
- When `AWS_ACCESS_KEY_ID` is unset on the host, `--aws` reads the `access_key_id` and `secret_access_key` fields, plus optional `session_token` and `region`, of the 1Password item in `CLAUDE_DOCKER_AWS_OP_REF` (a trailing `/` is tolerated, and a host `AWS_REGION` wins over the item's region). (0001)
- In a non-ephemeral box `/home/claude/.aws` is always an empty tmpfs owned by the box user, with or without `--aws`; the read-only `config` and `sso` mounts sit on top of it, so no AWS file written in one box is visible in another. (0001)
- `--gh` forwards a host `GH_TOKEN` or `GITHUB_TOKEN`; when neither is set it reads `CLAUDE_DOCKER_GITHUB_OP_REF` with `op read`, and only when that ref is unset does it try `gh auth token --hostname <host>` on the host for each GitHub host (default `github.com`) and forward the first token as `GH_TOKEN`. (0001)
- The GitHub host list is `CLAUDE_DOCKER_GITHUB_HOSTS` when set, otherwise the dotted top-level host keys of the host `~/.config/gh/hosts.yml`, and `run.sh` forwards it to the box as `CLAUDE_DOCKER_GITHUB_HOSTS`. (0001)
- `--glab` mounts no glab config and forwards `GITLAB_TOKEN` from the host env or `op read "$CLAUDE_DOCKER_GITLAB_OP_REF"`, plus `GITLAB_HOST` and `CLAUDE_DOCKER_GITLAB_HOSTS` when set on the host; no GitLab host is derived from the host glab config. (0001)
- The SBP launchers `cd-cis`, `cd-inat`, `cd-asr`, `cd-ta` and `cd-apg` export `GITLAB_HOST` and `CLAUDE_DOCKER_GITLAB_HOSTS`, both `sbp.gitlab.schubergphilis.com`, before they start `run.sh`. (0001)
- `--tfe` and `--tofu` each mount the host `~/.terraform.d/credentials.tfrc.json` read-only at `/home/claude/.terraform.d/credentials.tfrc.json` when it exists and forward `TF_TOKEN_app_terraform_io`; `--tofu` also mounts the host `~/.tofurc` read-only at `/home/claude/.tofurc`, and the two flags combine freely. (0001)
- `--tfe` and `--tofu` target `app.terraform.io` only; self-hosted Terraform Enterprise hosts and other `TF_TOKEN_<host>` variables are not forwarded. (0001)
- `--ado` forwards `AZURE_DEVOPS_EXT_PAT` from the host env or `op read "$CLAUDE_DOCKER_ADO_OP_REF"`, with no bind mount, and forwards `CLAUDE_DOCKER_ADO_HOSTS` (default `dev.azure.com`) for the git credential helper. (0001)
- `--jira` forwards `JIRA_USER_EMAIL`, `JIRA_BASE_URL` and `JIRA_API_TOKEN` with no bind mount; only the token falls back to `op read "$CLAUDE_DOCKER_JIRA_OP_REF"`, and no git credential helper is set up for Jira. (0001)
- A fresh in-container `gh auth login` under `--gh` persists across runs in the `claude-code-root` volume. (0001)
- In a non-ephemeral box `~/.config/gh/` is masked by an empty tmpfs unless `--gh` is set without a GitHub profile, `~/.config/glab-cli/` is always masked, and `~/.terraform.d/` is masked unless `--tfe` or `--tofu` is set. (0001)
- With `--gh`, `--glab` or `--ado` and a token present, the entrypoint sets, for each host in `CLAUDE_DOCKER_GITHUB_HOSTS` (default `github.com`), `CLAUDE_DOCKER_GITLAB_HOSTS` (default `gitlab.com`) or `CLAUDE_DOCKER_ADO_HOSTS` (default `dev.azure.com`), `credential.https://<host>.username oauth2` and an inline helper that prints the token from `${GH_TOKEN:-$GITHUB_TOKEN}`, `$GITLAB_TOKEN` or `$AZURE_DEVOPS_EXT_PAT` at auth time. (0001)
- No git `insteadOf` rewrite is configured, so URL-printing git commands show bare `https://<host>/` URLs and no token value is written to any git config file. (0001)
- The credential helpers live in `/tmp/claude-docker-gitconfig`, which `/etc/gitconfig` includes, so they vanish with the container, never reach the home volume, and a user's own `--global` or `--local` git config wins. (0001)
- A token containing control characters is skipped for git credential injection with one stderr warning naming its host group; the other groups are unaffected. (0001)
- A credential flag never starts a box without its credential: `run.sh` aborts before `docker run`, naming the flag or ref, when `op` is missing but needed, the `op whoami` preflight fails, any required `op read` fails, or none of the flag's variables ended up set. (0001)
- `CLAUDE_DOCKER_OP_OPTIONAL=1` turns each credential-gate abort into a warning and the launch continues without that credential; it never softens a GitHub or ADO profile abort. (0001)
- The end-state check covers `--gh`, `--glab`, `--ado`, `--ado-admin`, `--jira`, `--supabase`, `--cloudflare`, `--openrouter`, `--sonar`, `--cis`, `--mepdb`, `--braindb`, `--brain`, `--rr-e2e` and `--hetzner-infra`, and not `--aws`, `--tfe` or `--tofu`, whose credentials may arrive by mount. (0001)
- A failed `op whoami` preflight is reported once, naming every flag that needed 1Password, with no per-ref read errors after it; each `op read` is capped at `CLAUDE_DOCKER_OP_TIMEOUT` seconds (default 5). (0001)
- `--cis` forwards `CIS_API_KEY` from the host env or `op read "$CLAUDE_DOCKER_CIS_OP_REF"`, with no default ref and no mount, and adds `cis` to `CLAUDE_DOCKER_FLAGS`. (0001)
- `--npm-feed` sets `NPM_FEED_PASSWORD` to the base64 of the box's `AZURE_DEVOPS_EXT_PAT`, without line breaks, and adds `npm-feed` to `CLAUDE_DOCKER_FLAGS`; without `--ado` it aborts naming both flags, and without `--npm-feed` the variable is never forwarded. (0001)
- `--supabase` forwards `SUPABASE_ACCESS_TOKEN` from the host env or `op read "$CLAUDE_DOCKER_SUPABASE_OP_REF"`, with no default ref, mount or git helper, and adds `supabase` to `CLAUDE_DOCKER_FLAGS`. (0001)
- `--cloudflare` forwards `CLOUDFLARE_API_TOKEN` (host env or `op read "$CLAUDE_DOCKER_CLOUDFLARE_OP_REF"`) and `CLOUDFLARE_ACCOUNT_ID` (host env only), each when non-empty, with no default ref, mount, `wrangler login` path or git helper; it adds `cloudflare` to `CLAUDE_DOCKER_FLAGS`, and the account id alone does not satisfy the flag. (0001)
- `--openrouter` forwards `OPENROUTER_API_KEY` from the host env or `op read "$CLAUDE_DOCKER_OPENROUTER_OP_REF"`, with no default ref, mount, CLI-login fallback or git helper, and adds `openrouter` to `CLAUDE_DOCKER_FLAGS`. (0001)
- `--sonar` forwards `SONAR_TOKEN` (host env or `op read "$CLAUDE_DOCKER_SONAR_OP_REF"`) and `SONAR_HOST_URL` (host env only), each when non-empty, with no default ref, mount, CLI-login fallback or git helper; it adds `sonar` to `CLAUDE_DOCKER_FLAGS`, and the URL alone does not satisfy the flag. (0001)
- `--ado-admin` forwards `AZURE_DEVOPS_ADMIN_PAT` from the host env or `op read "$CLAUDE_DOCKER_ADO_ADMIN_OP_REF"`, with no default ref or mount, beside and never instead of `AZURE_DEVOPS_EXT_PAT`; it is not wired into the git credential helper or `az devops`, and adds `ado-admin` to `CLAUDE_DOCKER_FLAGS`. (0001)
- `--mepdb` forwards `POSTGRES_TEST_URL` from the host env or `CLAUDE_DOCKER_MEPDB_OP_REF` (default `op://claude-docker/brain-test-postgres/dsn`; an explicitly empty value turns 1Password off), with no mount or git helper, and adds `mepdb` to `CLAUDE_DOCKER_FLAGS`. (0001)
- `--braindb` forwards `BRAIN_TEST_DSN` from the host env or `CLAUDE_DOCKER_BRAINDB_OP_REF` (default `op://claude-docker/laslo-brain-test-postgres/dsn`; an explicitly empty value turns 1Password off), with no mount or git helper, and adds `braindb` to `CLAUDE_DOCKER_FLAGS`. (0001)
- `--braindb` runs the box on the single docker network of the running `brain-test-postgres` container and rewrites the DSN's host and port to `brain-test-postgres:5432`, keeping scheme, credentials, database and query string. (0001)
- `--braindb` aborts before `docker run`, naming the flag and never printing the DSN, when `brain-test-postgres` is not running or sits on zero or several networks, when the DSN is not a `scheme://` URL, or when `--host-net` or `CLAUDE_DOCKER_NETWORK` already chose a network. (0001)
- `--rr-e2e` forwards `E2E_EMAIL`, `E2E_PASSWORD`, `E2E2_EMAIL`, `E2E2_PASSWORD`, `SUPABASE_URL` and `SUPABASE_ANON_KEY`, each when non-empty, and adds `rr-e2e` to `CLAUDE_DOCKER_FLAGS`; the Supabase pair comes from the host env only. (0001)
- Each `--rr-e2e` account variable not set on the host is read from the `username` or `password` field of `CLAUDE_DOCKER_RR_E2E_OP_ITEM` (default `op://claude-docker/RingRecipe e2e account`) or `CLAUDE_DOCKER_RR_E2E2_OP_ITEM` (default `op://claude-docker/RingRecipe e2e2 account`); an empty item turns that account off, and either password satisfies the flag. (0001)
- `--hetzner-infra` forwards `HCLOUD_TOKEN` from the host env or `CLAUDE_DOCKER_HETZNER_OP_REF` (default `op://claude-docker-infra/hcloud-mep/token`; an explicitly empty value turns 1Password off), with no mount or git helper, and adds `hetzner-infra` to `CLAUDE_DOCKER_FLAGS`. (0001)
- The Hetzner read uses the service-account token in `CLAUDE_DOCKER_HETZNER_OP_TOKEN_FILE` (default `${XDG_CONFIG_HOME:-~/.config}/op/infra-service-account-token`) for that one read only and never forwards it; an explicitly empty file setting uses the everyday account instead. (0001)
- A missing, empty or non-`ops_` Hetzner token file is reported by path, never content, and counts as a failed read; while a token file is in use, a failed everyday `op whoami` preflight does not block a launch whose only 1Password read is this one. (0001)
- `--brain`, or `CLAUDE_DOCKER_BRAIN=1` in the launching environment (every `cd-*` launcher sets it unless already set), forwards `BRAIN_CF_ACCESS_CLIENT_ID` and `BRAIN_CF_ACCESS_CLIENT_SECRET` and adds `brain` to `CLAUDE_DOCKER_FLAGS`. (0001)
- The Brain values come from the host env, or else from `CLAUDE_DOCKER_BRAIN_CF_ID_OP_REF` and `CLAUDE_DOCKER_BRAIN_CF_SECRET_OP_REF` (defaults `op://claude-docker/brain-cf-access/username` and `op://claude-docker/brain-cf-access/credential`); no secret value is kept in a committed file or in `~/.claude.json`. (0001)
- When both Brain variables are set, the entrypoint makes sure a user-scope HTTP MCP entry `brain` exists for `https://brain.karansjet.dev/mcp`, with the literal placeholder headers `CF-Access-Client-Id: ${BRAIN_CF_ACCESS_CLIENT_ID}` and `CF-Access-Client-Secret: ${BRAIN_CF_ACCESS_CLIENT_SECRET}`. (0001)
- Under the same condition the entrypoint makes sure a user-scope HTTP MCP entry `family-board` exists for `https://family.karansjet.dev/mcp` with the same placeholder headers; an existing `brain` or `family-board` entry is left untouched, and a failed add only warns. (0001)
- `CLAUDE_DOCKER_ADO_PROFILE` in the launching environment (ignored in the claude-docker env file; a name outside `[a-z0-9]+` aborts) makes an `--ado` box a profile box, tagged `ado:<name>` in `CLAUDE_DOCKER_FLAGS`. (0001)
- A profile box takes its PAT only from `op read "$CLAUDE_DOCKER_ADO_<NAME>_OP_REF"` and its orgs only from the comma list `CLAUDE_DOCKER_ADO_<NAME>_ORGS` (each `[A-Za-z0-9-]+`, case kept); it drops a host `AZURE_DEVOPS_EXT_PAT` and ignores `CLAUDE_DOCKER_ADO_OP_REF`, `CLAUDE_DOCKER_ADO_ORG` and `CLAUDE_DOCKER_ADO_HOSTS`. (0001)
- A profile box aborts before `docker run` when its op-ref is unset, its read fails or returns nothing, or its org list is empty or invalid; `--ado-admin` under a profile aborts without reading any admin PAT, and without `--ado` or `--ado-admin` the profile variables do nothing. (0001)
- In a profile box the git credential helper answers only for `https://dev.azure.com/<org>` and paths below it, for each profile org, and the token probe makes one request per org. (0001)
- `CLAUDE_DOCKER_ADO_LABEL` from the launching environment (ignored in the env file) changes only the `CLAUDE_DOCKER_FLAGS` tag of a default `--ado` box to `ado:<label>`; a profile box keeps `ado:<profile>`. (0001)
- When the home volume is mounted, the persisted `az devops` state in `~/.azure/azuredevops` and `~/.azure-devops` is visible only to a default `--ado` box; every other box, profile boxes included, gets empty box-owned tmpfs dirs there that do not persist. (0001)
- `CLAUDE_DOCKER_GITHUB_PROFILE` in the launching environment (ignored in the env file; a name outside `[a-z0-9]+` aborts) makes a `--gh` box take its token only from `op read "$CLAUDE_DOCKER_GITHUB_<NAME>_OP_REF"`. (0001)
- In a GitHub profile box, a `GH_TOKEN` or `GITHUB_TOKEN` from the host or env file, the default `CLAUDE_DOCKER_GITHUB_OP_REF` and the host `gh` login never reach the box, the git helper covers `github.com` only, the stored `gh` login is masked, and a missing ref or failed read aborts the launch. (0001)
- After the credential gate passes and before `docker run`, `run.sh` probes each forwarded token with an identity request, in parallel with a 1 s connect and 2 s total timeout, passing the token to `curl` on stdin so it never appears in argv or `run.sh` output. (0001)
- Probe endpoints: `--gh` `api.github.com/user`; `--glab` `https://<host>/api/v4/user` for `CLAUDE_DOCKER_GITLAB_HOSTS` (default `gitlab.com`); `--ado` and `--ado-admin` `dev.azure.com/<org>/_apis/connectionData` per org in `CLAUDE_DOCKER_ADO_ORG`; `--jira` `$JIRA_BASE_URL/rest/api/3/myself`; `--supabase` `api.supabase.com/v1/projects`. (0001)
- Probe endpoints, continued: `--cloudflare` `api.cloudflare.com/client/v4/user/tokens/verify` and, when `CLOUDFLARE_ACCOUNT_ID` is set, `accounts/<id>/tokens/verify`; `--openrouter` `openrouter.ai/api/v1/key`; `--sonar` `${SONAR_HOST_URL:-https://sonarcloud.io}/api/authentication/validate`; `--tfe` `app.terraform.io/api/v2/account/details`; `--hetzner-infra` `api.hetzner.cloud/v1/locations?per_page=1`. (0001)
- `--aws`, `--tofu`, `--tfe` without `TF_TOKEN_app_terraform_io`, `--mepdb`, `--braindb`, `--rr-e2e`, `--cis`, `--brain`, and an ADO flag with no `CLAUDE_DOCKER_ADO_ORG` are not probed. (0001)
- A rejected token (401; for `--glab` 401 on every probed host; for `--cloudflare` 401 or 403 on every check; for `--sonar` also 200 with `"valid":false`) prints one stderr line naming the flag and status, and the launch continues; a network error, timeout, 5xx or other status prints nothing. (0001)
- Rejected flags reach the box as `CLAUDE_DOCKER_REJECTED_TOKENS`, comma-separated without leading dashes, and the statusline shows them as a red `token-dead:<flags>` tag; `CLAUDE_DOCKER_NO_TOKEN_PROBE=1`, or no `curl` on PATH, skips every probe. (0001)

## CLI help

- `run.sh` treats `-h` and `--help` before `--` as wrapper flags: when its argument loop reaches one it prints usage to stdout and exits 0, before defaulting the workspace to `$PWD`, creating the `$HOME/.cache/claude-docker/host.*` staging dir, copying host config or calling Docker, so it also succeeds on a host with no `docker` binary. (0001)
- `-h` or `--help` after `--` is forwarded verbatim to `claude` in the container (`claude-docker -- --help` runs `claude --help`, `claude-docker ~/repo -- -h` runs `claude -h`) and never prints the wrapper's usage. (0001)
- The usage text gives every flag label in `run.sh`'s argument `case` statement a human-readable description on the same or the next line, grouped under "Wrapper flags" apart from the `--` separator section. (0001)
- The usage text also documents the `--` passthrough contract, positional workspaces and their default to `$PWD`, `CLAUDE_DOCKER_TMUX` (`1` plain tmux, `cc` tmux -CC), `CLAUDE_DOCKER_CONFIG_DIR` as the env form of `--claude-dir`, and that `settings.docker.json` is mounted read-only as a seed and copied onto a writable `settings.json` on every container start. (0001)

## Container network

- `run.sh` passes `--network <name>` to `docker run` only when a network is selected, taken from `CLAUDE_DOCKER_NETWORK` or set to `host` by `--host-net` (the flag wins), and then adds `net:<name>` to `CLAUDE_DOCKER_FLAGS`; with neither, `--braindb` is the only other source of a `--network` argument (the `brain-test-postgres` network), and without it the default bridge is used. (0001)
- Selecting a network leaves the filesystem mounts, `--cap-drop ALL` and `no-new-privileges` unchanged, and `--help` lists `--host-net` and `CLAUDE_DOCKER_NETWORK` and says the container then loses network isolation. (0001)

## Container user

- The box runs as uid 1000 / gid 1000, user `claude` with `HOME=/home/claude`: the image's `USER 1000:1000` covers a bare `docker run`, and `run.sh` passes `--user 1000:1000`, `--cap-drop ALL` and `--security-opt no-new-privileges` and adds no capability back. (0001)
- The image adds no sudo and no setuid binary and the entrypoint starts unprivileged, never as root dropping privileges later, so `id -u` in the box prints `1000`, its effective capability set is empty, and files it writes through a `/mnt/c` bind mount are owned by the WSL user. (0001)
- The image pre-creates, owned by uid 1000, the home dirs that runtime mounts sit on (`~/.claude`, `~/.config/gh`, `~/.config/glab-cli`, `~/.aws`, `~/.terraform.d`, `~/.azure/azuredevops`, `~/.azure-devops`, `~/.local/bin`, `~/.venvs`, `~/.inat/rules`), and makes `/root` a symlink to `/home/claude` so absolute `/root/...` paths recorded by earlier root-run boxes still resolve. (0001)
- The entrypoint exits non-zero, pointing at the one-off volume migration in `claude-docker/README.md`, when `~/.local/bin`, `~/.claude` (checked when a `settings.docker.json` seed is mounted) or `~/.aws` (checked when static AWS keys are forwarded) is not writable by the box user. (0001)

## Host config parity

- `run.sh` reads every host config item from one directory: `--claude-dir=PATH`, else `CLAUDE_DOCKER_CONFIG_DIR`, else `~/.claude`, with a leading `~/` in either expanded to `$HOME`. (0001)
- From that directory `agents/`, `commands/` and `skills/` are staged with `cp -RL` (after resolving a top-level symlink, at most 10 hops) into `$HOME/.cache/claude-docker/host.XXXXXX` and mounted read-only at `/home/claude/.claude/<item>`, so internal symlinks resolve in the box; the stage sits under `$HOME` because Colima shares only `$HOME` with its VM, and it is removed when `run.sh` exits. (0001)
- `CLAUDE.md` is mounted read-only at `/home/claude/.claude/CLAUDE.md`, and the host `statusline-command.sh` is mounted read-only as `statusline-command.original.sh` behind a generated wrapper at `statusline-command.sh` that prefixes a yellow `docker:<CLAUDE_DOCKER_FLAGS>` tag when that variable is set. (0001)
- The host `hooks/` directory and the host `settings.json` are never forwarded; the wrapper's own `claude-docker/hooks/` directory is copied into the stage instead and mounted read-only at `/home/claude/.claude/hooks`, active only where the seed settings wire its commands. (0001)
- When `<config-dir>/settings.docker.json` exists it is mounted read-only at `/home/claude/.claude/settings.docker.json` and the entrypoint copies it onto a writable `/home/claude/.claude/settings.json` on every start, so in-session writes such as `/effort` succeed instead of failing with `EBUSY`; without it no host-derived settings file reaches the box and Claude uses its defaults. (0001)
- That `settings.json` copy lives on the shared `claude-code-home` volume, so each box start resets it to the seed for every running non-ephemeral box and a live `/effort` change is seen by any box's next `claude` start; only an `--ephemeral` box keeps its own copy. (0001)
- The image sets `IS_SANDBOX=1` so `claude --dangerously-skip-permissions` (the `--yolo` shortcut) launches without a refusal; the box narrows the blast radius but is not a full sandbox, per the threat model in `claude-docker/README.md`. (0001)
- `examples/settings.docker.json` allows exactly `Read(~/.claude/skills/**)`, `Read(~/.inat/rules/**)` and `Read(~/.claude/CLAUDE.md)` without a prompt, for the Read tool and read-only Bash commands such as `head` on those paths; it adds no other allow rule, other commands still prompt, and its deny rules (such as `Read(//**/.env)`) still block a path under an allowed directory. (0001)
- `--claude-auth` bind-mounts `<config-dir>/.credentials.json` read-write at `/home/claude/.claude/.credentials.json`, so host and box use one OAuth token and a host re-login reaches the box without a 401 or `/login` prompt, and adds `auth` to `CLAUDE_DOCKER_FLAGS`; without the flag the host credential file is never mounted. (0001)
- With `--claude-auth` and no host `<config-dir>/.credentials.json`, `run.sh` prints an error naming the path and telling the user to run `claude` and `/login` on the host, and exits 1 before `docker run`; `--help` warns that a `--yolo` box can then read and write the host Claude credential. (0001)
- `run.sh` resolves the config dir to its real path and, when `<its parent>/.inat/rules` is a directory, mounts that directory and nothing else of `.inat` read-only at `/home/claude/.inat/rules`, under `--ro` and `--ephemeral` too; when it is absent nothing is mounted there, and one warning naming the checked path is printed only if the host `CLAUDE.md` contains `~/.inat/rules/`. (0001)
- The image provides `/home/claude/.inat` owned by the box user, so in-box inat can still write beside the read-only rules mount (for example `~/.inat/cache`). (0001)

## Launchers

- `cd-brain` (`brain-test-postgres`) and `cd-mep` (`myentrypoint-test-postgres`) take a shared `flock` on `~/.cache/claude-docker/locks/<container>.lock` before bringing their test database up and hold it until the box exits, so a box still between `up --wait` and `docker run` counts as running. (0001)
- On exit, normal or by HUP, INT or TERM (exit 129, 130, 143), such a launcher stops every container of the database's compose project with `docker stop` only if it can take the lock exclusively without waiting, never removes containers, networks or volumes, prints `<container> stopped (last box out)` or `<container> left running: another box holds it`, and exits with the box's status whatever the stop did. (0001)
- A launch that starts during a stop waits up to 60 s for the shared lock and then brings the database back up with its previous data; on a lock timeout, or with no `flock` on the host, it says so and leaves the database up after its box. (0001)
- `cd-brain` brings its database up with `op run --env-file=.env.test -- docker compose -f compose.test.yml up -d --wait`, retries with `--force-recreate` when container port 5432 is not published, and aborts before the box when `127.0.0.1:47401` is still not published; `cd-mep` does the same from `compose.test.env` but only warns (`127.0.0.1:47304`) and launches anyway. (0001)
- `cd-up` holds a fixed box list split over three Windows Terminal windows, `cd-q1` (`apg asr`), `cd-q3` (`tools dev mep`) and `cd-q4` (`brain cis ct inat`); with no names it relaunches them all, with names only those, each at most once, and an unknown name exits 2 listing the valid names before any check or tab. (0001)
- `cd-up` takes `--yolo` (passed to every box it opens, never the default) and `--work` or `--home` before the names, and `-h` or `--help` prints its usage line to stdout and exits 0; both desk flags together, or any other option, exit 2 before any check or tab. (0001)
- `cd-up` waits up to `CD_UP_DOCKER_WAIT` seconds (default 180) for `docker info`, then skips each requested box whose container is running (by its `claude-docker.box` label) with `cd-up: skipped cd-<name> (already running)`, and exits 0 with `cd-up: nothing to open` and no further check when none is left; Docker not coming up or a failing `docker ps` prints one line and exits 1 with no tab. (0001)
- `cd-up` then checks `op whoami` once and, if it fails, prints that 1Password is not authenticated and exits 1 with no tab. (0001)
- For each remaining box `cd-up` makes one `wt.exe -w cd-<window> new-tab --title cd-<name>` call, `CD_UP_STAGGER` seconds apart (default 3), running `cd-<name>[ --yolo] -- --continue` under `bash -lic` and leaving an interactive shell in the tab when the box exits or fails; the command holds no `;`, and a tab whose group window is already open joins it. (0001)
- With `--work`, each group window this run creates is moved through the Windows API to exactly its quarter (1280x1392 at x 0, 2560 and 3840, y 0) while windows that already existed stay put, and a failed placement prints one warning while the tabs still open; `--home` has no rectangles yet, so it prints `cd-up: no home placement yet; windows unplaced` and moves nothing. (0001)
- `launchers/_lib.sh` exports `CLAUDE_DOCKER_BOX` as the launcher's own name and `run.sh` labels the container `claude-docker.box=<that name>` (empty when `run.sh` runs directly), so `docker ps --filter label=claude-docker.box=cd-<name>` lists that box only. (0001)

(0001)
- `cd-inat` launches with `--gh` and `--glab`, `CLAUDE_DOCKER_GITHUB_PROFILE=inat` and `CLAUDE_DOCKER_GITHUB_INAT_OP_REF` defaulting to `op://claude-docker/inat-github-ro/credential`, and keeps its GitLab settings (`GITLAB_HOST` and `CLAUDE_DOCKER_GITLAB_HOSTS` set to `sbp.gitlab.schubergphilis.com`). ## Workspace mounts

- `run.sh` mounts each positional host directory at `/workspaces/<basename>` (no argument: `$PWD`) and aborts when a basename holds a character outside `A-Za-z0-9._-`. (0001)
- Two different host paths with the same basename abort before `docker run` with an error naming both; the same path given twice collapses to one mount. (0001)
- `claude` starts in the first workspace's container path, and every further workspace is passed as `--add-dir <container path>` without deduping against a user `--add-dir` after `--`; a single workspace adds no `--add-dir`. (0001)
- Arguments after the first `--` go verbatim to `claude` (a further bare `--` is dropped); before it, `--yolo` becomes `--dangerously-skip-permissions` on the `claude` command, ahead of the passthrough flags. (0001)
- `--ro` mounts every workspace read-only, so writes fail with EROFS while `--add-dir` still lists them, and adds `ro` to `CLAUDE_DOCKER_FLAGS`. (0001)
- The image's git is 2.48 or newer (Ubuntu 26.04 base), so it accepts `extensions.relativeWorktrees`; a worktree nested in a mounted repo (e.g. `<repo>/.claude/worktrees/<name>`) whose repo has `worktree.useRelativePaths true` works for `status`, `log`, `diff`, `commit`, `worktree add` and `worktree list` in the box and back on the host without `git worktree repair`, given host git 2.48 or newer. (0001)
- A repo and its sibling worktree passed as separate workspaces are flattened under `/workspaces/`, so git across them may need one `git worktree repair` in the box, relative paths or not; hosts with git older than 2.48 use this repair flow for every layout. (0001)
- When a workspace strictly contains the directory holding `run.sh`, that directory is bind-mounted read-only over its path inside the workspace mount while the rest of the workspace keeps its mode; the overlay is skipped under `--ro`, under `--tools`, and when the workspace is the launcher directory itself. (0001)
- When `CLAUDE_DOCKER_BUS_DIR` names an existing directory and `--no-bus` is not given, the box gets one mailbox keyed by its first workspace: its path relative to the bus dir's parent with `/` turned into `.` (`laslo/ringrecipe` becomes `laslo.ringrecipe`), or its basename when it is not under that parent. (0001)
- `run.sh` creates `<bus>/<key>/in` and `<bus>/<key>/out`, mounts `<bus>/<key>` read-write at `/bus` with `<bus>/<key>/in` read-only over `/bus/in`, and sets `AGENT_BUS_DIR=/bus`, `AGENT_BUS_SELF=<key>` and `SLACK_OUTBOX_QUEUE=/bus/.slack-outbox/queue`, under `--ro` and `--ephemeral` as well. (0001)
- No other box's mailbox and no parent of `<bus>/<key>` is reachable: when a workspace mount contains the bus dir, `run.sh` masks it there with an empty tmpfs, under `--ro` and `--no-bus` too. (0001)
- `CLAUDE_DOCKER_BUS_DIR` unset or empty mounts no mailbox and prints nothing; a missing directory, or a key that is empty, starts with `.` or holds a character outside `A-Za-z0-9._-`, prints a warning and launches without a mailbox. (0001)

## Bundled tools and package managers

- The image ships `uv`, `uvx`, `pnpm` and `pnpx` on the default PATH for amd64 and arm64; `uv` and `uvx` are the glibc (`unknown-linux-gnu`) build, and `pnpx` is pnpm 10's alias for `pnpm dlx`. (0001)
- `uv` is pinned by `ARG UV_VERSION` and checked with `sha256sum -c` against `UV_SHA256_X86_64` or `UV_SHA256_AARCH64`, kept in the Dockerfile, before extraction, so a mismatched tarball or a version bump without new hashes fails the build. (0001)
- Every build-time `npm install -g` runs with `--ignore-scripts`: the one npm line installs `@fission-ai/openspec@${OPENSPEC_VERSION}` and `pnpm@${PNPM_VERSION}`, while `claude` itself is a native binary pinned by `CLAUDE_CODE_VERSION` and a per-architecture sha256. (0001)
- `pnpm dlx <pkg>` runs a package from the npm registry without adding it to the global `node_modules`, like `npx`. (0001)
- `uvx <pkg>` runs a PyPI tool in an ephemeral environment with no Python preinstalled: uv fetches a Python runtime and the package and caches both for later runs. (0001)
- The image ships Go at `/usr/local/go`, pinned by `ARG GO_VERSION` and checked with `sha256sum -c` against `GO_SHA256_X86_64` or `GO_SHA256_AARCH64` before extraction. (0001)
- Dockerfile `ENV` puts `/usr/local/go/bin` and `/home/claude/go/bin` on PATH and sets `GOPATH=/home/claude/go` (in the `claude-code-root` volume) with no `GOROOT`, so Claude's Bash tool finds `go` and `go install`ed tools persist and resolve without a shell rc. (0001)
- The image ships the OpenSpec CLI (`openspec`, npm package `@fission-ai/openspec`) on the default PATH for amd64 and arm64, pinned by exactly one `ARG OPENSPEC_VERSION` line. (0001)
- The OpenSpec CLI needs no host state and adds no `run.sh` flag, help entry, mount, forwarded variable or volume. (0001)
- Project-specific runtimes (rust, ruby and the like) stay out of the base image and belong in child images built `FROM claude-code:local` and launched through `CLAUDE_DOCKER_IMAGE`; Go, Flutter and .NET are the exceptions baked in. (0001)
- The `claude-docker/README.md` threat model's runtime code-fetch bullet names `npx`, `pnpm dlx`, `uvx`, `tfenv install`, `tofuenv install`, `go install`, `go run <module>@<version>` and Go toolchain auto-download (`GOTOOLCHAIN=auto`) as fetching and running code from public sources, which a prompt-injected workspace can trigger under `--yolo`. (0001)
- That bullet marks `uvx` (PyPI) and `tfenv install` / `tofuenv install` (HashiCorp and OpenTofu releases, binaries not pinned in the image) as new execution primitives, and `pnpm dlx` as adding nothing beyond `npx`. (0001)
- The README's "Bundled CLIs on the default PATH" line lists `uv`, `uvx`, `pnpm`, `pnpx`, `tfenv`, `tofuenv` and `go` with the other bundled CLIs. (0001)

## Session storage

- Unless `--ephemeral` is given, `run.sh` mounts the named volume `claude-code-root` at `/home/claude` and `claude-code-home` at `/home/claude/.claude`, so session files, credentials and project records outlive the `--rm` container. (0001)
- Every workspace's sessions live under the one `/home/claude/.claude/projects/` tree, so `claude --resume` with Ctrl+A lists the sessions of every workspace used in earlier runs. (0001)
- `--ephemeral` skips both volumes and the credential tmpfs masks that sit on them and adds `ephemeral` to `CLAUDE_DOCKER_FLAGS`: `/home/claude/.claude/projects/` starts empty, and no OAuth token, `gh` login, shell history or session history persists or reaches either volume. (0001)

## Session worklog

- The wrapper ships `hooks/session-worklog.py` (mounted at `/home/claude/.claude/hooks`), and `examples/settings.docker.json` wires it: `start` on SessionStart, `report` on PreToolUse and `touch` on PostToolUse for Edit, Write, MultiEdit and NotebookEdit, and `stop` on SessionEnd. (0001)
- `touch` records the repository of each edited file in a per-session index, and the repositories holding the working directory at `start` and at `stop` are added when they are repositories, so a subrepo edited from a non-repo parent such as `/workspaces/dev` is found. (0001)
- On `stop`, each recorded repository gets one NDJSON line appended to `<git common dir>/claude-sessions/worklog.ndjson` (`<repo>/.git/claude-sessions/`: never committed, shared by every box that mounts the repo) with session id, timestamp, event, repo path, branch, `dirty_tracked` and `untracked` counts, and `ahead`/`behind` (null with no upstream), all from one `git status --porcelain=v2 --branch` call. (0001)
- The record describes changes as counts only, never changed file paths, contents or diff hunks, and carries no per-session history (start/end HEADs, commit counts, diffstat); when no repository was touched, nothing is written and the hook exits 0. (0001)
- On SessionEnd, a repository with uncommitted, untracked or unpushed work gets a stderr warning naming the repo, the branch and what is outstanding; a clean, pushed tree prints nothing. (0001)
- `report`, which `start` also runs for the working-directory repository, reads the tail of that repository's `worklog.ndjson` and, when its last record was dirty or ahead, emits the warning once per repository per session as `hookSpecificOutput.additionalContext`, without re-checking live git state; an event outside any repository emits nothing. (0001)
- Directory-to-repository lookups are cached per session under `/tmp`, so only the first edit in a directory runs git, and the per-session files under `/tmp` are deleted at SessionEnd. (0001)
- The hook runs only `git rev-parse` and `git status` and never commits, pushes, stashes, prunes, cleans, resets or removes anything; any error goes to stderr with exit 0, so it can never fail or delay a session. (0001)
